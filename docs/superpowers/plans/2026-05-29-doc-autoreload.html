Live document auto-reload in the SPA

Goal Make the docs-hub SPA auto-refresh the open screen every 30 s so new versions and new docs appear without a manual reload — the viewer auto-swaps its iframe to a newer version when tracking latest. Frontend-only; one file (public/app.js); no backend, DB, or API change.

01

Tasks

Four small tasks, each ending in a commit. Tasks 1–2 are prep with syntax-check + smoke checks; Task 3 delivers the observable auto-reload; Task 4 is the full verification pass. No JS test harness exists (spec §08) — so each task is guarded by node --check plus a manual browser check, with pytest as the backend regression. A spec-sanctioned deviation from automated TDD, not an oversight.

Task 1

Force-refresh path in the data layer

loadDocs(force=false) and loadVersions(slug, force=false) refetch and overwrite the cache when forced; unchanged for existing zero-arg callers (LSP-verified: all calls are in render()). On a forced loadVersions failure, keep prior data rather than clobbering to [].

public/app.jsnode --check + smoke
Task 2

Signatures & last-rendered tracking

Add sigIndex / sigVersions / sigViewer and a module-level _lastSig stamped at the end of render(). The viewer signature is the resolved displayed version — the gate that keeps a pinned /v<n> view from reloading. No behaviour change yet.

public/app.jsnode --check + smoke
Task 3

Poll loop + boot wiring

One 30 s route-aware setInterval: pollTick force-refreshes the current screen's data and calls maybeRerender, which re-renders only on a signature change (and defers while a filter input is focused). Pauses on a hidden tab, fires once on reshow. The functional payoff — viewer auto-swap, live index & log.

Task 4

Verification & regression

Final node --check, .venv/bin/pytest -v (backend untouched), confirm POLL_MS = 30_000 (not a shortened test value), walk the spec §06 checklist, and clean up the throwaway probe doc.

02

Poll-tick flow

One tick. The signature gate (clay diamond) is what prevents the iframe from reloading every 30 s when nothing changed — the core of the design.

A failed refresh is swallowed (skip, retry next tick) so a blip never tears the screen into the error view. On the index, render() is deferred while a filter input is focused.

03

Key code

The two pieces most likely to be done wrong: the viewer signature (must key off the displayed version, not the version list) and the poll tick (route-aware, failures swallowed).

public/app.js · viewer signature
// keys off the ONE version on screen,
// not the whole list. /v<n> resolves to n
// (never changes on publish → no reload);
// bare slug resolves to latest (bumps →
// iframe swaps).
function sigViewer(route) {
  const doc = (_docs || [])
    .find((d) => d.slug === route.slug);
  return String(
    route.version ??
    (doc && doc.latest_version) ?? '?');
}
public/app.js · poll tick
const POLL_MS = 30_000;

async function pollTick() {
  if (document.visibilityState === 'hidden')
    return;
  const route = parseRoute();
  try {
    if (route.name === 'index') {
      await loadDocs(true);
      maybeRerender(sigIndex());
    } else if (route.name === 'viewer') {
      await loadDocs(true);
      await loadVersions(route.slug, true);
      maybeRerender(sigViewer(route));
    } else if (route.name === 'versions') {
      await loadDocs(true);
      await loadVersions(route.slug, true);
      maybeRerender(sigVersions(route.slug));
    }
  } catch (e) { /* skip, retry next tick */ }
}
04

Risks & mitigations

Risk
Sev
Mitigation
Unconditional re-render reloads the iframe every tick, resetting scroll even with no new version.
HIGH
The signature gate (sig === _lastSig → skip) is mandatory and is the core of the design; re-render happens only on real change.
Re-rendering the index mid-interaction blows away input focus / open select.
MED
Focus guard: skip the index re-render while document.activeElement is inside .filterbar; apply on the next tick.
A poll fetch fails (server restart, blip) and tears the screen into the error view.
LOW
fetchJSON's 5xx-retry plus a try/catch that swallows tick failures — a failed tick is skipped, the next one recovers.
Viewed version is deleted out from under the reader.
LOW
Next re-render resolves to the existing renderNotFound — already the behaviour for a missing version.
05

Verification

Each box is exercised in Task 3 and re-confirmed in Task 4. Run the app with .venv/bin/uvicorn backend.app:app --port 8084 and publish a throwaway probe slug to make a version land while watching.

Viewer auto-swap. Bare #/d/<slug> on latest; publish → iframe updates and counter advances within ~30 s.
Pinned view left alone. On an explicit /v<n>; publish → no swap, scroll preserved.
Index live-update. On #/; publish → row appears / version bumps.
Filter focus guard. Typing in search while a version lands → no mid-keystroke re-render; updates after blur.
Version log live-update. On …/versions; publish → new row, latest badge moves.
Quiescence. No publishing → iframe not reloaded each tick; polling pauses on hidden tab.
Regression. node --check public/app.js + .venv/bin/pytest -v green; POLL_MS = 30_000.
