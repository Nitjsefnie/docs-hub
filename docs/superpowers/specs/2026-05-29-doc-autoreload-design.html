Design spec · docs-hub

Live document auto-reload in the docs-hub SPA

Context The docs-hub SPA (public/app.js) renders a published artifact in a sandboxed iframe, but caches /api/list and /api/versions/<slug> once and never refreshes — a reader sitting on a doc never sees a newer version land. This spec adds a polling loop so that, every 30 s, the currently-open screen reflects new versions and new docs automatically. Frontend-only; no backend changes.

Decision
One global, route-aware poll loop in app.js that re-fetches the current screen's data every 30 s and re-renders only when a cheap signature changes.
Chosen over per-screen timers (more lifecycle surface, duplicated fetch logic) and server push / SSE (needs backend work, a publish-time event hook, and Cloudflare stream proxying — overkill for a feature with 30 s latency tolerance). A single timer reads location.hash each tick, so it covers all three screens with one lifecycle and no per-navigation cleanup.
On the document viewer the new version is auto-swapped into the iframe the moment it is detected (no banner, no click). The accepted cost is that the iframe scroll resets to the top on swap. A reader who has deliberately navigated to an older version is never swapped off it.
01

Background

What the current SPA does, and the precise gap this closes.

The SPA is hash-routed with three screens: index (#/), version log (#/d/<slug>/versions), and the document viewer (#/d/<slug> / #/d/<slug>/v<n>). The viewer renders chrome plus a sandboxed <iframe> whose src is the raw artifact route /d/<slug>/v<n>. The raw route serves agent-published HTML with no app.js — so all watching and reload logic must live in the SPA shell, never in the iframe payload.

The data layer caches permanently: loadDocs() fills module-level _docs once; loadVersions(slug) fills _versions[slug] once. There is no refresh path and no timer. The viewer already computes isStale = ver !== latest and shows a v{ver} / v{latest} counter — so the "am I on the latest?" signal already exists; what is missing is fresh data and a trigger.

02

Approach chosen

Single global poll loop vs. the alternatives.

Rejected
  • Per-screen timers started in each wire*() and cleared on route change — three lifecycles, duplicated fetch logic, no gain now that every screen is live.
  • Server push (SSE/WebSocket) — true realtime, but needs a backend event endpoint, a publish-time hook, Cloudflare stream proxying, and connection lifecycle. Disproportionate to a 30 s tolerance.
Chosen
  • One global setInterval started once at boot.
  • Each tick reads parseRoute(), re-fetches only that screen's data, overwrites the cache, and re-renders only if a signature changed.
  • One timer, one lifecycle; pauses on hidden tab, fires once on re-show.
  • No backend change — the endpoints already return everything needed and the API JSON is not edge-cached.
03

Per-screen behaviour

"Live" means something different on each screen. The re-render rule is per-route. The signature gate is the load-bearing guard everywhere — without it the viewer iframe would reload every 30 s even with no new version, needlessly resetting scroll.

ScreenPollsRe-render when…Effect
Viewer
#/d/<slug>		 /api/list + /api/versions/<slug> the resolved displayed version changes — i.e. a bare #/d/<slug> (tracking latest) and latest bumps iframe src → new version; auto-swaps (scroll resets to top). Any route pinned to an explicit /v<n> — even /v<latest> — never re-renders, so the reader is left in place.
Index
#/		 /api/list list signature changes (new doc, version bump, updated_at) table re-renders. Skipped while a filter input/select has focus (document.activeElement inside .filterbar); deferred to next tick. FILTER state is global, so filters survive a re-render.
Version log
#/d/<slug>/versions		 /api/list + /api/versions/<slug> version-list signature changes a new row appears; latest badge moves.
04

Change inventory

Every edit lands in public/app.js. No other file changes.

public/app.js · loadDocs / loadVersions
Add a force path. loadDocs(force=false) and loadVersions(slug, force=false): when force is true, fetch fresh and overwrite the cache; otherwise behave exactly as today. Normal navigation stays cached; the poller always forces.
public/app.js · new sig helpers
Add per-screen signature functions. A cheap deterministic string capturing exactly what each screen displays — so the gate fires only when the visible output would actually change. Index: slug|latest_version|updated_at per row, joined. Version log: the version list's version|sha256 joined. Viewer: the single resolved displayed version — the pinned /v<n> if the route has one, else latest_version. This is the critical distinction: the viewer must not key off the whole version list, or a new version landing would reload the iframe of a reader pinned to an older version (a full render() recreates the iframe element). Keying off the resolved version means a bare-slug viewer swaps when latest bumps, while a pinned viewer never moves.
public/app.js · render()
Stamp the last-rendered signature. On every normal render(), store the current screen's signature in a module-level _lastSig so the first poll after a navigation compares against what is actually on screen.
public/app.js · new startPolling()
Add the poll loop, call it once at boot. A 30 s setInterval (interval as a named const). Each tick: bail if tab hidden; parseRoute(); force-refresh the relevant data; compute the new signature; if changed (and not blocked by the focus guard on index), re-render the current screen via the existing render(). A visibilitychange listener triggers an immediate refresh when the tab is re-shown.
05

Data & control flow

One tick of the loop, in pseudocode. The fetch path reuses fetchJSON, whose existing 5xx-retry covers transient blips; a failed tick is swallowed (skip, try next) so a blip never tears the screen into the error view.

const POLL_MS = 30_000;

async function pollTick() {
  if (document.visibilityState === 'hidden') return;   // paused when tab hidden
  const route = parseRoute();
  try {
    if (route.name === 'index') {
      await loadDocs(true);                              // force-refresh _docs
      maybeRerender(sigIndex());                         // honours filterbar focus guard
    } else if (route.name === 'viewer') {
      await loadDocs(true);                              // refreshes latest_version
      await loadVersions(route.slug, true);              // refreshes the new version object
      maybeRerender(sigViewer(route));                   // resolved DISPLAYED version only
    } else if (route.name === 'versions') {
      await loadDocs(true);
      await loadVersions(route.slug, true);
      maybeRerender(sigVersions(route.slug));            // whole version list
    }
  } catch (e) { /* swallow — try next tick */ }
}

// Viewer gate: the ONE version on screen, not the list. A pinned /v<n> route
// resolves to n (never changes on publish → no reload); a bare slug resolves to
// latest (bumps when a new version lands → iframe swaps).
function sigViewer(route) {
  const doc = (_docs || []).find(d => d.slug === route.slug);
  return String(route.version ?? doc?.latest_version ?? '?');
}

function maybeRerender(sig) {
  if (sig === _lastSig) return;                          // signature gate: nothing changed
  if (indexFilterFocused()) return;                      // defer if user is filtering
  render();                                              // render() re-stamps _lastSig
}

The "only swap when tracking latest" rule is enforced by sigViewer, not by luck. A bare #/d/<slug> resolves to latest_version; when a new version lands, that number changes, the gate fires, render() re-points the iframe at the new version, and it swaps (scroll resets — accepted). A route pinned to /v<n> resolves to n, which a new publish never changes — so the signature is unchanged, the gate does not fire, and no re-render happens at all (the iframe element is never recreated, so scroll is preserved). The v{n} / v{m} counter's {m} therefore lags on a pinned view until the reader navigates — a deliberate trade documented in §08.

06

Verification

The pytest suite covers the API, not SPA JS, and the repo has no JS test harness — so this feature is verified manually in the browser. Bolting on a JS runner for one feature is out of scope (see §08).

Viewer auto-swap. Open #/d/<slug> on the latest version; publish a new version via the CLI; within ~30 s the iframe shows the new version and the v{n} / v{m} counter advances.
Stale view is left alone. Navigate to an older /v<n>; publish a new version; the iframe does not swap and scroll position is preserved.
Index live-update. Sit on #/; publish a new doc / new version; the row appears or the version bumps within ~30 s.
Filter focus guard. Type in the search box while a version lands; the table does not re-render mid-keystroke; it updates on the next tick after focus leaves.
Version log live-update. Sit on #/d/<slug>/versions; publish; a new row appears and the latest badge moves.
No-change quiescence. Leave a viewer open with no publishing; confirm via DevTools that the iframe is not reloading each tick (signature gate holds) and that polling pauses on a hidden tab.
Regression. .venv/bin/pytest -v still green (no backend change expected, but confirm).

Risks

Risk
Sev
Mitigation
Unconditional re-render reloads the iframe every tick, resetting scroll even with no new version.
HIGH
The signature gate (sig === _lastSig → skip) is mandatory and is the core of the design; re-render happens only on real change.
Re-rendering the index mid-interaction blows away input focus / open select.
MED
Focus guard: skip the index re-render while document.activeElement is inside .filterbar; apply on the next tick.
Auto-swap yanks a reader off the version they are reading.
LOW
Accepted for the latest view (the explicit product choice). Older pinned versions are never swapped. Scroll-reset on swap is a documented, accepted cost.
A poll fetch fails (server restart, blip) and tears the screen into the error view.
LOW
fetchJSON's 5xx-retry plus a try/catch in the tick that swallows failures — a failed tick is skipped, the next one recovers.
Viewed version is deleted out from under the reader.
LOW
Next re-render resolves to renderNotFound — acceptable and already the behaviour for a missing version.
08

Out of scope

Considered and deliberately deferred — named so the reader knows they were weighed, not missed.

Server push (SSE / WebSocket)
True realtime instead of 30 s polling. Deferred: needs backend + Cloudflare stream work disproportionate to the latency tolerance. Revisit only if polling load or latency becomes a real complaint.
A JS test harness
No JS runner exists in the repo; this feature is verified manually. Adding Jest/Vitest + jsdom for one feature is not justified here — propose separately if SPA JS grows enough to warrant it.
Configurable / adaptive interval
Fixed 30 s const. Backoff when idle or a user-set interval are unnecessary for current usage.
In-place counter update for stale views
When viewing an older version, the v{n} / v{m} counter's {m} can lag until navigation. Updating just that text without a full re-render is possible but not worth the added code path.
