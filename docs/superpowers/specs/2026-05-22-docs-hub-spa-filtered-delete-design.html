SPA wiring & filtered delete

TL;DR — Two changes to docs-hub. (1) Apply the docs.zip front-end: the hash-routed SPA moves into public/, gets mounted as static files, replaces the server-rendered index in views.py, and is rewired to fetch live data from /api/* instead of the mock data.js (which is dropped). (2) Add POST /api/delete — a filtered, whole-doc delete with a mandatory dry-run preview and an HMAC confirm token, so a destructive bulk delete can never run unconfirmed or unfiltered.

Part 1 — Apply docs.zip: wire the SPA to the backend

docs.zip contains a self-contained client-side SPA mockup (Docs Hub.html, app.js, styles.css, data.js). It is hash-routed (#/, #/d/<slug>, #/d/<slug>/v<n>, #/d/<slug>/versions) and currently renders entirely from window.DOCS / window.VERSIONS mock data in data.js. The backend today server-renders an index table from backend/views.py and has no static-file mount. This part makes the SPA the real front-end backed by live data.

app.py & routing

  • app.py mounts the SPA: StaticFiles serving public/, with public/index.html returned for GET /.
  • views.py: the server-rendered index() route (GET /) and its _INDEX_HEAD template are removed — / now serves the SPA shell.
  • views.py: render_latest (GET /d/{slug}) and render_version (GET /d/{slug}/v{n}) stay. They return the raw artifact HTML and are the src targets of the SPA doc-viewer <iframe>. No collision: the SPA is hash-routed, so #/d/... is never sent to the server while server /d/... paths still resolve.
★
Mount ordering matters: the static mount for / must not shadow /api/*, /d/*, /login, /logout, /health. Routers are included first; the catch-all static mount is added last (or scoped so it only serves known asset paths plus /).

Auth interaction

The existing auth_middleware treats / as non-public: an unauthenticated visitor is redirected to the real server-side /login page (from login.py). Therefore the SPA is only ever served to a logged-in human.

  • The SPA's own #/login screen and its hardcoded uid==='19' / 'hunter2' check are removed — the server /login page is the single source of auth.
  • The SPA top-bar "logout" link points at the server /logout route.
  • The fake top-bar user 19 label is replaced with the real session user id, exposed by a tiny GET /api/whoami endpoint returning {ok, user_id} for the current principal.

Part 2 — Filtered delete endpoint

A new POST /api/delete removes whole documents (a doc row plus all its versions and all its blobs) selected by a filter set. Because a filter can match many docs at once, the endpoint is built around a mandatory two-step dry-run → confirm handshake.

Authentication

Accepts either the agent API key or a human session cookie. The auth_middleware already admits both principals for /api/*, so — unlike /api/publish — the delete handler does not call _require_agent. Both a CLI agent and a logged-in human in the SPA can call it.

Filters

All fields optional, combined with AND. The matched set is "whole docs"; filters that name a version attribute match a doc by its latest version.

FieldMatches
slugExact slug.
projectdocs.project exact.
authorposted_by of the latest version.
tagTag present in docs.tags[].
qCase-insensitive substring of title or slug.
updated_before / updated_afterISO-8601 bound on docs.updated_at.
!
An empty filter set is rejected with 400. The endpoint will never match-all — deleting every document requires explicit per-filter intent.

Dry-run + confirm token

Preview
Filters, no confirm_token.
→
SERVER
Match + sign
Returns matched docs, count, and an HMAC token over the normalized filters.
→
CALL 2
Confirm
Same filters + the confirm_token.
→
SERVER
Delete
Re-derives token, deletes rows + blobs, returns count.
  • The token is HMAC-SHA256(SESSION_SECRET, canonical_filters + "." + issued_at), carried as <issued_at>.<hmac>. Reuses the SESSION_SECRET already used for session cookies; lives in session.py alongside the cookie helpers.
  • TTL ≈ 5 minutes. A stale token is rejected — the caller must re-preview.
  • The token binds to the canonical filter set: the confirm call recomputes the HMAC from its own filter params and compares. A token previewed for project=A cannot be replayed to delete project=B.
  • Canonicalization: filter keys sorted, empty values dropped, values trimmed — so semantically equal filter sets produce the same token regardless of param order.

400  { "ok": false, "error": "at least one filter required" }

# token expired or filters changed since preview
409  { "ok": false, "error": "confirm token invalid or expired" }

# neither API key nor session cookie  (from middleware)
401  { "ok": false, "error": "Unauthorized" }

# confirm matched zero docs (e.g. deleted meanwhile)
200  { "ok": true, "preview": false, "deleted": 0 }

Delete execution

For each matched doc, in one transaction per doc: delete the docs row — doc_versions rows cascade via the existing ON DELETE CASCADE FK — then remove the blob directory <STORE_ROOT>/<slug>/ via a new storage.delete_doc(slug). Blob removal is best-effort-logged but a missing directory is not an error (idempotent). DB delete commits before blob removal so a crash leaves orphan blobs (harmless) rather than orphan rows.

Testing

TDD per the repo convention — failing test first, then minimal implementation. New / extended pytest coverage:

  • test_storage.py — delete_doc removes the dir; no-op on a missing dir; rejects an invalid slug.
  • test_docs_repo.py — find_docs for each filter and AND-combinations; delete_docs removes rows + versions + blobs; list_docs now carries byte_size.
  • test_session.py — delete-token round-trips; rejects a tampered token, an expired token, and a token whose filters were changed.
  • test_app.py — POST /api/delete preview returns a token and deletes nothing; confirm deletes; empty filters → 400; bad/expired token → 409; no auth → 401; agent key and human cookie both accepted; GET / serves the SPA shell; static assets resolve; /d/{slug} still renders raw HTML.

End-to-end check after wiring: log in, load /, confirm the SPA index lists real docs, open a doc, preview then confirm a filtered delete, confirm the doc is gone from the index and the blob directory is removed.

Out of scope

  • Single-version deletion. Delete operates on whole docs only. Removing one version of a multi-version doc (which would require recomputing latest_version and could leave a doc with zero versions) is not built. A version filter is therefore not offered.
  • A delete control inside the SPA UI. The endpoint is reachable by the agent CLI and by a logged-in human via direct call, but no delete button/affordance is added to the SPA screens in this change.
  • Server-side index filtering. The index keeps client-side filtering over the full /api/list result; /api/list is not extended with tag/q/sort params.
  • Undo / soft-delete / trash. Delete is permanent.
